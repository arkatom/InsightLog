### 研修Issue設計で実装詳細を含めてしまった（2回）

- **原因の推定**: prompt — 受講生の前提知識（コードベースを知らない）を理解していたはずが、Issue文面を書く段階で開発者目線に戻ってしまった

### 「CLAUDE.mdの有無で差が出る」提案の失敗
- **何が起きたか**: 研修の主旨を「CLAUDE.mdの有無による差」と解釈して案を出したが、ユーザーから「Claude Codeが賢すぎて差が出ない」と指摘され、「指示の具体性の差」に方針転換
- **原因の推定**: prompt — ユーザーの要望「CLAUDE.mdの内容を理解した上で指示を具体的に出す効果」の読み取りが浅かった。「CLAUDE.mdの有無」ではなく「理解した上で具体的に」が本質だった
- **どう解消したか**: 「指示の具体性」に切り口を変え、解釈が割れる曖昧な要望（案B）で着地

## 得られた知見

- 研修コンテンツのIssueは「受講生が見て画面のどこか分かる」レベルで書く。ファイル名・関数名・ライブラリ名は出さない
- Claude Codeの探索能力が高いため、「情報の有無」より「指示の解釈の幅」で差を設計する方が研修効果が出る
- Zustandストアと設定（IndexedDB）の同期は、idle状態のときだけuseEffectで行うパターンが安全
- Custom Commandsは実質deprecated。Skillsへの移行が公式推奨
