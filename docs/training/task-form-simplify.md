# 実習: 曖昧な要望を具体化して解く

## 受け取った要望

こんな要望を受け取ったことありませんか？ **わざと曖昧にしてある要望** を、自分で具体化してから Claude Code に渡し、実装・動作確認までやりきる練習です。

> タスクの記録をもっと簡単にしてください。毎回要素を選び直すのが面倒です。

この要望をそのまま AI に渡しても良い結果は出ません。**自分で「何が面倒で、どう解決するか」を具体化してから** 渡します。

## 🎯 理想の完成形

前回選択した **AI ツール** と **カテゴリ** が、次のタスク記録時に **初期値として再表示される** 状態。

この状態に持っていくために、曖昧な Issue をどう具体化するかを自分で考えて、指示文として書き出します。

## ゴール

- 曖昧な Issue を具体的な指示に変換する経験を積む
- 「どのファイルを変えるか」は AI に任せる（自分で考えなくていい）
- InsightLog に記録まで完了する

## 進め方（35分）

### Phase 1 — 思考時間（7分・各自）

**手は動かさない。頭で考える時間です。**

以下を順に考えてください：

1. **何が面倒なのか？**
   - カテゴリを毎回選ぶのが面倒？
   - AI ツール選択が面倒？
   - 時間入力が面倒？
   - 振り返りメモを書くのが面倒？

2. **どう改善するのか？**
   - 前回の値を保持する？
   - よく使うプリセットを作る？
   - 入力欄を減らす？
   - デフォルト値を賢くする？

3. **指示文として書き出す**

    Claude Code に渡せる粒度の文章にする。例:

    ```
    TaskForm で、前回選択したカテゴリと AI ツールを
    次回の初期値にしてほしい。
    ```

    対象（TaskForm）と動作（初期値にする）を明確に。

> **ヒント**: 完璧な解決案じゃなくていいです。「何が面倒で、どうしたいか」を1文で言えれば OK。

### Phase 2 — Claude Code に渡す（20分・各自）

1. Phase 1 で書いた指示文を Claude Code に渡す
2. 実装が返ってきたらブラウザで動作確認（`npm run dev` が動いている前提）
3. 思った通りでなければ、さらに指示を追加して修正
4. いい感じになったらここでいったん完了

> **大事**: 完成が目的ではありません。**具体化する過程** と **指示を出して動作確認するサイクル** を経験することが学びです。

### Phase 3 — InsightLog に記録（5分）

InsightLog のタスク記録フォームに以下を入力：

| 項目 | 何を書くか |
|------|-----------|
| タスク名 | 例: タスク記録フォームの改善 |
| AIツール | Claude |
| 所要時間 | 実測値 |
| AI 未利用時の推定 | 自力だったら何分かかるか |
| 手戻り回数 | 指示のやり直し回数 |
| カテゴリ | 機能追加 / UX 改善 など |
| 振り返りメモ | **特に大事**: 最初の指示で何が足りなかったか、具体化した後に何が変わったか |

## 詰まったら

- **何が面倒か思いつかない**: 実際にタスク記録を1回やってみる。手を動かすと不満が見える
- **どう指示していいか分からない**: まず1文で書いてみる。Claude Code が質問を返してくれる
- **実装が思った通りにならない**: 最初の指示と今の指示を見比べて、何が曖昧だったか言語化する
- **時間内に終わらない**: 完成が目的ではない。そこまでの過程を Phase 3 で記録する

## 完成の定義

- [ ] 自分で Issue を具体化した（Phase 1）
- [ ] Claude Code に指示を渡して変更が入った（Phase 2）
- [ ] ブラウザで変更を確認した
- [ ] InsightLog に振り返りメモまで書いて記録した（Phase 3）
