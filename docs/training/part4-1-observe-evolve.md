# 実習: 振り返りと改善サイクルを体験

## ゴール

事前に配置されたデモ用の振り返りデータを使い、**/observe** と **/evolve** の2つのスキルで改善サイクルを一周する。AI の提案を鵜呑みにせず、自分で採否を判断する経験を積む。

## 前提

- Claude Code が起動していること
- `docs/memory/reflection/` にデモ用の振り返りファイルが配置されていること
- `docs/memory/heartbeat/improvements.md` に3件の改善提案（proposed）が配置されていること

## Step 1: /observe を実行（5分）

1. Claude Code で以下を実行:

    ```
    /observe
    ```

2. observe スキルがデモ用の振り返りデータを分析し、以下を出力する:
   - セッションの品質採点（Rubric スコア: 10点満点）
   - 摩擦ポイントの検出
   - 改善提案の生成（あれば）

3. 出力を読み、スコアの根拠が納得できるか確認する

## Step 2: 改善提案を確認（5分）

`docs/memory/heartbeat/improvements.md` を開き、3件の proposed を確認する:

| # | 提案内容 | Risk-level |
|---|---------|------------|
| 1 | CLAUDE.md にコンポーネント配置ルール追記 | high |
| 2 | npm run dev 自動実行フック追加 | high |
| 3 | ユーザー制約ヒアリング強化 | high |

> **Note (2026-05-07 改修)**: 全 3 件を `Risk-level: high` に統一済。`/evolve` Step 3b の「高リスク人間キュー」に全件入り、受講者は **3 件すべての採用・却下を判断する** 設計。低リスク自動適用は本実習では発火しない。

**考えてみてください**:
- それぞれの提案は、リスクに見合う効果がありそうか？
- 過剰な自動化になっていないか？
- 全部採用する必要はあるか？

## Step 3: /evolve を実行（8分）

1. Claude Code で以下を実行:

    ```
    /evolve
    ```

2. evolve スキルが各提案について採用・却下を聞いてくる
3. 自分の判断で **採用 / 却下** を決定する

    **ヒント**: 2件目の「npm run dev 自動実行フック」は、ファイル編集のたびに dev サーバーが再起動される。負荷が高すぎるので **却下が妥当** という判断も正解

4. 採用した提案が設定に反映されたことを確認する

## 振り返り（記録項目）

InsightLog に以下を記録してください:

| 項目 | 何を書くか |
|------|-----------|
| タスク名 | 改善サイクル体験（observe + evolve） |
| AIツール | Claude |
| 所要時間 | 実測値 |
| AI 未利用時の推定 | 手動でレビュー・設定変更したら何分かかるか |
| 手戻り回数 | 0（デモデータのため） |
| カテゴリ | その他 |
| 振り返りメモ | **特に大事**: 3件のうち何件を採用し、何件を却下したか。判断基準は何だったか |

## 完成の定義

- [ ] /observe を実行して Rubric スコアを確認した（Step 1）
- [ ] 3件の改善提案を読み、自分なりの判断を持った（Step 2）
- [ ] /evolve を実行して採否を判断した（Step 3）
- [ ] InsightLog に振り返りメモまで書いて記録した

## 詰まったら

- **/observe がエラーになる**: デモ用の振り返りファイルが配置されているか確認。`ls docs/memory/reflection/` で1件以上あること
- **/evolve で何を採用すべかわからない**: 正解はない。「過剰な自動化」と「効果的な自動化」の境界を自分で考えることが学び
- **improvements.md に proposed がない**: テンプレートの更新を取り込んでいない可能性がある。講師に確認
